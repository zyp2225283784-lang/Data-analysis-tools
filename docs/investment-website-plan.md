# 上市公司经营数据分析网站规划

## 1. 产品目标与边界

### 1.1 核心目标
- 聚合并结构化展示上市公司的经营与财务数据。
- 通过可视化图表帮助用户快速理解公司质量与变化趋势。
- 形成“数据看板 + 评分框架 + 研究结论”的投资辅助闭环。

### 1.2 非目标（初期不做）
- 不提供自动化交易、下单能力。
- 不提供个性化投顾建议（避免触发牌照与合规风险）。
- 不做高频行情终端型产品（聚焦中长期基本面分析）。

## 2. 目标用户与使用场景

### 2.1 用户画像
- 个人投资者：希望快速完成一家公司的基础面研读。
- 进阶投资者：希望跨公司、跨行业比较财务质量与估值。

### 2.2 关键场景
1. **公司深度页**：查看单一公司 5~10 年经营趋势与核心指标。
2. **对比分析**：2~5 家公司同屏比较增长、盈利、现金流、估值。
3. **预警监控**：当出现毛利率恶化、现金流转弱、负债率异常时提醒。
4. **研究笔记**：记录假设、结论与后续跟踪点。

## 3. 数据体系设计

### 3.1 数据分层
- **原始层（Raw）**：财报、公告、行情、行业分类等原始数据。
- **标准层（Standardized）**：统一币种、会计口径、财报周期。
- **特征层（Feature）**：同比、复合增速、利润质量、杜邦拆解等。
- **应用层（Serving）**：前端图表直接消费的宽表与聚合接口。

### 3.2 必备指标（建议 MVP）
- 增长：营收、净利润、扣非净利润 CAGR（3/5 年）。
- 盈利：毛利率、营业利润率、净利率、ROE、ROIC。
- 现金流：经营现金流/净利润、自由现金流、资本开支占比。
- 偿债：资产负债率、流动比率、利息保障倍数。
- 运营：存货周转天数、应收账款周转天数、总资产周转率。
- 估值：PE(TTM)、PB、EV/EBITDA、股息率（如适用）。

### 3.3 数据质量控制
- 同一指标至少保留“原值 + 计算值 + 数据来源 + 更新时间”。
- 建立异常值规则（如同比 > 500%、负值与口径冲突）。
- 建立财报重述追踪（Restatement）机制。

## 4. 功能模块规划

### 4.1 MVP（第一阶段，6~10 周）
1. 用户注册登录（邮箱或 OAuth）。
2. 公司列表与搜索（股票代码/公司名）。
3. 公司详情页：
   - 财务概览卡片；
   - 3~5 张核心趋势图（营收、利润、毛利率、经营现金流、ROE）；
   - 估值区间图（历史分位）。
4. 公司对比页（最多 3 家）。
5. 自选股与基础预警（阈值型）。

### 4.2 第二阶段
- 行业对比与分位排名。
- 文本解读（财报摘要、风险点提取）。
- 研究模板与导出报告（PDF）。

## 5. 技术架构建议

### 5.1 前端
- React + TypeScript + Next.js。
- 图表库：ECharts 或 Recharts（时间序列与多轴图支持更重要）。
- 状态管理：Zustand/Redux Toolkit（根据团队偏好）。

### 5.2 后端
- Python（FastAPI）或 Node.js（NestJS）。
- 提供 REST API（后续可补 GraphQL）。
- 核心服务拆分：认证服务、数据查询服务、指标计算服务、告警服务。

### 5.3 数据与计算
- OLTP：PostgreSQL（用户、自选股、配置）。
- OLAP：ClickHouse（时序财务与行情查询）。
- 缓存：Redis（热门公司指标缓存、限流）。
- 调度：Airflow/Prefect（每日或财报后增量更新）。

### 5.4 部署与运维
- 容器化：Docker + Kubernetes（或初期单机 Docker Compose）。
- 监控：Prometheus + Grafana。
- 日志：ELK 或 Loki。
- CI/CD：GitHub Actions。

## 6. 图表与分析框架建议

### 6.1 图表清单
- 趋势折线图：营收、净利润、经营现金流。
- 百分比堆叠图：成本结构、费用结构。
- 双轴图：营收增速 vs 净利率。
- 雷达图：盈利能力、成长性、偿债、运营效率综合对比。
- 估值分位图：当前 PE/PB 位于历史百分位。

### 6.2 研究框架（可产品化）
- “先质量后估值”：
  1) 商业模式与竞争壁垒；
  2) 财务质量（盈利 + 现金流 + 杠杆）；
  3) 增长持续性；
  4) 当前估值与安全边际。
- 输出统一的“研究结论卡”：看多/中性/谨慎 + 关键依据。

## 7. 合规与风险控制

- 显著位置添加免责声明：仅供信息展示，不构成投资建议。
- 记录数据来源与更新时间，避免“误导性实时数据”表达。
- 用户隐私合规（账户信息、访问日志、Cookie 管理）。
- 对外接口增加限流、防爬与鉴权策略。

## 8. 里程碑与团队配置

### 8.1 里程碑
- 第 1-2 周：需求冻结 + 原型图 + 数据模型设计。
- 第 3-5 周：数据管道 + 指标计算 + API。
- 第 6-8 周：前端页面 + 图表 + 对比功能。
- 第 9-10 周：联调、压测、灰度上线。

### 8.2 团队建议（最小配置）
- 产品经理 1 人。
- 前端工程师 1~2 人。
- 后端工程师 1~2 人。
- 数据工程师 1 人。
- 设计师 1 人（可兼职）。

## 9. 建议的下一步（你可以立刻执行）

1. 确定首批覆盖市场与公司池（例如美股/港股/A 股）。
2. 明确 20 个 MVP 指标的精确定义与口径。
3. 选定首个数据源方案并评估成本。
4. 画出 3 个核心页面线框图：公司页、对比页、自选页。
5. 用 2 家你熟悉的公司做“端到端试跑”（数据→图表→结论）。
